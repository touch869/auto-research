# 热点检测( ① 简单总结模式的增量 )

在 report 已检索的三源+社区数据上,**检测是否有爆发热点**,在周报里单独标出。
注意:**不做定时**——什么时候跑是 harness 的事,skill 只在被调用时对当前数据做热点判断。

## 热度信号( 综合判定,非单一指标 )
| 信号 | 来源 | 含义 |
|------|------|------|
| 社区讨论度 | HN points/comments、Reddit score | 业界关注度 |
| 短期密度激增 | 同一工作/主题在多源多次出现( 跨源去重前的计数 ) | 多源同时报道 = 爆发 |
| 引用增速 | arXiv meta( 若可得 )/Semantic Scholar | 学术影响力 |
| 高 star 增长 | GitHub repo | 工程热度 |

## 判定流程( 强模型 + 规则 )
1. **规则初筛**:跨源去重前,统计每个"工作/主题"的出现次数;社区条目按 points 排序取 Top。
2. **强模型判断**:对候选热点,综合判断"这是真热点还是常规进展",给出:
   - 是否热点( 是/否 )
   - 热度类型( 新突破 / 争议 / 开源爆款 / 行业事件 )
   - 一句话理由( 为什么热 )
3. **标注进周报**:在周报"值得看"之外,加一个 **## 本期热点** 段落,把判定为热点的条目突出展示。

## 与普通条目的区别
- 普通条目( 值得看 ):按相关+质量选,服务于"该看什么"。
- 热点条目:按**爆发度**选,服务于"最近什么在火"。一个条目可以既在"值得看"也在"热点"。

## 输出
热点结果并入 briefs.json 的 `hotspots` 字段( 见 report-template.md ),由 render_report.py 渲染。
没有热点时,该段落写"本期无明显爆发热点",**不硬造**。
