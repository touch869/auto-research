# 迭代检索循环 + 收敛判据 + 时效性

两模式共用的核心机制:搜索→分析→发现缺口→再搜索,直到收敛或达最大轮数。
对标 DeepResearcher/WebThinker 的"推理过程中不断搜索"。

## 循环结构
```
round = 0
queries = 主题解析的初始 query 集
history = []  # 累积所有轮结果( 去重后 )
while round < maxRounds:
    round += 1
    1. 检索:四源( arXiv/GitHub/Web/社区 )用本轮 queries
    2. 累积去重:新结果并入 history( scripts/dedupe.py )
    3. 分析:
       - 简单模式:浅分析( 相关性/质量/简评/热点 )
       - deep模式:深分析( 对核心材料读全文深挖 )
    4. 收敛判断( agent,见下 ):
       - 若"已收敛"( 无值得再搜的缺口 )→ break
       - 否则:生成下一轮 queries( 针对缺口 )→ 继续
综合 history → 渲染报告
```

## 收敛判据( agent 自判 A + 最大轮兜底 )
每轮分析后,agent 回答:
1. **信息缺口**:基于已收集材料,还有哪些关键问题/子方向/对比对象**没覆盖**?
2. **是否值得再搜**:这些缺口能否通过进一步检索填补?( 有的缺口是"材料不存在"或"需实验",搜不出来 → 不算可检索缺口 )
3. **判定**:
   - 无可检索缺口 → **收敛**,停止
   - 有可检索缺口 → 生成针对缺口的 query( 具体、可搜 ),进入下一轮

**业界 5 类停止判据**( 元研究自 Deep Research Agents 实践 ):
| 判据 | 含义 | 我们用? |
|------|------|---------|
| 迭代预算 | 硬上限( 如 LangChain:5 次 tool call ) | ✅ maxRounds 兜底 |
| 覆盖度 | 子话题都探索过 | ✅ agent 自判"缺口"含此 |
| 置信度 | 能自信回答就停 | ✅ agent 自判含此 |
| 收敛 | 新搜索收益递减/大量重复 | ✅ agent 自判 + iter_collect 去重计数辅助 |
| 成本预算 | token/$ 耗尽 | ⬜ 可选,暂未实现 |

**业界最佳实践 = 硬预算兜底 + 软判据( 覆盖/置信/收敛 )主停**( tianpan.co:无显式停止条件会无限循环,是最大工程难题 )。
→ **我们设计( agent 自判 A + maxRounds 兜底 )与之吻合**:软判据靠 agent 综合( 覆盖/置信/收敛 ),硬上限靠 maxRounds。

**最大轮数兜底**( 防失控 ):
- 简单模式:maxRounds 默认 3( 浅分析缺口耗得快,通常 2 轮收敛 )
- deep模式:maxRounds 默认 5( 深分析缺口多 )
- 达 max 仍不收敛 → 用现有材料出报告,在"未覆盖项"里列出剩余缺口。

**为什么简单模式自然收敛快**:它不做深度分析,每轮只能发现"漏了某个子方向/某个关键词",补几次就没了;不像 deep 会越挖越深。

## query 演化( 让每轮搜新东西 )
- 初始:主题直译 + 同义词 + 中英
- 后续轮:基于上轮分析发现的**新概念/新人物/新对比对象**生成 query
  - 例:第1轮发现"readiness-aware scheduling"是新概念 → 第2轮搜 `readiness-aware scheduling RL`、`CTB RA2P ERS`
  - 例:第1轮发现 prime-rl → 第2轮搜 `prime-rl vs ART`、`async RL training stability`
- **避免重复**:下轮 query 不能是上轮的子集( 去重已保证结果不重复,但 query 本身也要进化 )

## 时效性( 贯穿全程 )
1. **时间窗参数**:每轮检索都传 `--days`( 默认:简单 30 天、deep 180 天,可调 )。
2. **日期标注**:每条结果带 `date`,分析时关注;报告里每条显示日期。
3. **过时降权**:筛选时,超出时间窗或明显陈旧的( 如 2 年前且非奠基性 )降权;奠基性老论文( 如 RLHF 原始论文 )可保留但标注"经典/背景"。
4. **时效敏感主题**:对快速演进领域( 如 agentic RL ),优先近 3-6 个月;对成熟领域可放宽。
5. **报告头部**明示时间窗,让读者知道"这份综述覆盖到多新"。

## 输出
- 报告里可加"## 检索过程"( 可选 ):N 轮、每轮 query 演化、为何收敛 —— 增加可信度与可复现性。
