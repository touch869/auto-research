# 去重、过滤与筛选规则

report 模式 [3] 去重过滤 阶段的操作参考。

## 去重( scripts/dedupe.py )

机械去重交给脚本( 快、确定性 ):
```bash
python scripts/dedupe.py tmp/arxiv.json tmp/github.json tmp/web.json --out tmp/merged.json
```
规则( 双保险 ):
1. **URL 规范化**:去查询串/锚点/尾斜杠;`arxiv.org/pdf|html/` ≡ `arxiv.org/abs/`。
2. **标题归一化**:小写 + 去标点 + 压空格,完全相同视为重复。

**脚本去不了的重叠**:同一事件被论文和博客分别报道( 标题/URL 都不同 )。
→ 这类**语义近似去重交给强模型**,在"筛选 Top N"时一并处理:看到讲同一工作的多条,保留信息最全/最新的一条,其余并入其 `meta.related`。

## 相关性筛选

去重后,按相关性给每条打分,保留 Top N( 默认 N=5~10,可配置 ):
- 强模型判定:与主题的相关度( 0-5 )。
- **降权信号**:标题/摘要与主题关键词无交集;纯水文/营销。
- **加权信号**:高引用/高 star;顶会/知名团队;近期讨论热度高。

## 质量与新鲜度
- 时间窗:默认 7 天,可放宽。优先最新。
- 跨源平衡:尽量三源都有代表,别全压一边( 如全 arXiv )。

## 输出
筛后保留的条目 → 进入简评阶段( 强模型写 brief )→ 喂给 `render_report.py`。
